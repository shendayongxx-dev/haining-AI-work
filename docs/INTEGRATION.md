# 集成骨架接入说明

本项目是 A 维护的单一 React + TypeScript 网站骨架。各成员在同一项目中接入模块，不另建完整网站。当前代码为可浏览流程的演示实现，不等于完整 Demo 或工艺验收。

## 启动与构建

```bash
pnpm install
pnpm dev
pnpm build
```

当前锁文件为 `pnpm-lock.yaml`。Node.js 版本需满足 Vite 7 的要求（20.19+ 或 22.12+）。

## 接入位置

| 负责人 | 接入点 | 输入与交付 |
| --- | --- | --- |
| A | `src/App.tsx` 的页面状态和候选确认 | 管理载体、输入版本、候选、确认结果及 `designRevision`；新候选确认前保留旧正式设计。 |
| C | `src/modules/c/generateCandidate.ts` | 三通道生成；扇面输出 `surface_pattern`，自定义形状输出 `carrier_shape`；C→D 坐标为 mm。输入页布局与状态仍由 A 维护。 |
| D | `src/modules/d/FanPreview.tsx` | 确认结果和编法后生成网格、竹条、交织结构、SVG 及同版本 D→E 快照。编辑页布局与版本状态仍由 A 维护。 |
| E | `src/modules/e/validation.ts` | 按 D 快照及 B 的依据输出检查、材料、编号和教程；版本变化时使旧结果失效。检查与资料页布局仍由 A 维护。 |
| B | `docs/CRAFT_RULES.md`（待补）及标准案例 | 提供有来源、经实物验证的尺寸、编法和工艺规则。 |

公共字段及单位遵循 [`DESIGN_DATA.md`](DESIGN_DATA.md) V0.2。接口调整应先说明受影响模块并共同评审。

模块负责人优先在对应 `src/modules/<字母>/` 下开发。需要新增公共类型、改变 A 管理的状态，或改动 `src/App.tsx` 时，先与 A 对齐再提交 PR。视觉、Logo、页面布局仍由 A 迭代，不应作为模块接入的前置条件。

## 当前可用与限制

- 页面路径：选载体 → 三通道输入 → 生成中 → 候选确认 → 选编法 → SVG 编辑 → 工艺检查 → 制作资料。
- 绘制入口记录笔迹，支持鼠标、触屏、触控笔、撤销、重做和清空；目前尚未将实际笔迹转译成 C 的正式图形 JSON。
- 文字和参考图入口收集输入；生成结果暂用明确标注的联调候选。参考图只在本地选择，尚无 `assetRef` 上传及读取接口。
- 编辑页的参数、配色和编法切换会更新演示 SVG 与设计版本；此 SVG 不是 D 的正式竹条结构。
- 改变载体将返回输入与确认流程。现有正式设计在确认新候选前保留。
- 缺少 B 的工艺依据时，检查状态保持“待验证”，正式材料和教程不可生成或导出。

## 首个共同案例

扇面、直接绘制、绿色闭合三角形。C 交付稳定 `patternId`、`elementId`、有限色板、`polygon` 和 mm 坐标；D 读取同一结果生成 SVG 和结构快照；A 验证候选确认与版本失效。此案例只是联调起点，首版 Demo 仍须完成三个输入通道及自定义形状流程。
