# 请团队评审：设计数据与 SVG 实时预览方案

> 发给 A、B、C、D、E 共同评审。本文件是讨论稿，不代表接口或工艺规则已定稿。详细字段草案见 [DESIGN_DATA.md](DESIGN_DATA.md)。请直接在仓库提出修改建议，或按文末格式回复 A。

## 已确认的产品范围

- 扇面与自定义形状均支持参考图、自然语言描述、用户绘制三种输入，并走通生成确认、选编法、编辑与实时预览、工艺检查、材料清单、竹条编号和图文教程。
- 扇面生成适配载体的**表面图样**；自定义形状生成**几何载体形状**。箱盒、包仅展示选项。
- 实时调节与预览使用 **SVG**，不使用 Grasshopper。

## 提议的模块交接

1. **C 输入生成**：把三类输入转成结构化结果。扇面输出图样网格，自定义形状输出几何边界；保留输入引用和生成版本。
2. **A 确认与流程**：让用户预览、重新生成或确认结果；未确认不能进入正式编辑和检查。
3. **D 编辑与 SVG**：读取已确认结果、所选编法和参数，计算竹条数据并绘制 SVG。疏密、宽度、图样大小和配色变化时，同步更新设计版本与画面。
4. **E 检查与教程**：读取当前设计版本及竹条数据，输出问题、材料、编号和步骤；设计变化后旧检查和教程失效。
5. **B 工艺依据**：补充编法、竹条规格、参数边界、材料计算和真实制作顺序，并注明资料来源与试编状态。

## 请重点核对的接口问题

| 负责人 | 请确认或提出修改 |
| --- | --- |
| C | 三类输入是否都能输出可编辑的图样网格或闭合几何？自定义形状出现多部件、开口或复杂轮廓时如何表示和提示？ |
| D | SVG 统一用毫米设计坐标及 `viewBox` 映射是否合适？竹条路径、方向、颜色、交织顺序由谁计算、如何交给 E？参数变化能否稳定重算？ |
| E | 检查和教程还需要哪些字段？材料和编号应直接读取竹条数据还是另算？缺工艺依据时如何阻止误标“可制作”？ |
| B | 哪些扇面尺寸、编法、竹条规格和规则已有依据？自定义形状的可编织性可以先验证到什么程度？哪些结论必须等试编？ |
| A | 页面状态、用户确认、设计版本和旧教程失效规则是否足够支撑两条完整流程？ |

## 暂定共同规则

- 设计数据是唯一当前数据源；SVG 是其视图，不用 SVG 图片反推材料清单。
- 几何和尺寸统一使用 `mm`；页面缩放、平移不改变设计数据。
- 修改形状、图样、编法或工艺参数后递增设计版本，并使旧检查和教程失效。
- 缺少 B 的工艺依据时，可展示标注为“演示预览”的 SVG，检查状态为“待验证”，不得宣称可制作。
