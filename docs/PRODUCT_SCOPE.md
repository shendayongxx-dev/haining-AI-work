# 竹编 DIY 平台：产品范围（草案）

> 供五人团队审核。本文定义目标和本轮 Demo 验收范围，不表示功能已经实现。依据：《竹编DIY平台_五人协作与搭建流程.md》。

## 平台目标

用户依次选择载体、输入创意、确认生成结果、选择编法、调整参数并实时预览、接受工艺检查，最后获得与当前设计一致的材料清单、竹条编号和图文教程。

| 载体 | 生成结果 | 本轮 Demo 范围 |
| --- | --- | --- |
| 扇面 | 适配扇面的表面图样 | **本轮实现目标：完整流程** |
| 箱盒 | 未来生成适配箱盒的表面图样 | **本轮仅界面展示选项**，不实现生成或后续流程 |
| 包 | 未来生成适配包的表面图样 | **本轮仅界面展示选项**，不实现生成或后续流程 |
| 自定义形状 | 生成载体形状，并非表面图片 | **本轮实现目标：交互生成形状，并继续完成编法、编辑、检查和教程** |

## 本轮实现目标：扇面与自定义形状完整闭环

1. 选择扇面；选择参考图、自然语言或用户绘制输入通道并输入创意。
2. 生成适配扇面的表面图样，供用户预览和明确确认；未确认时不进入编法编辑。
3. 选择经工艺负责人确认的基础编法；展示图样在扇面和该编法下的竹条效果。
4. 调整疏密、竹条宽度、图样大小和配色；预览与当前设计数据同步更新。
5. 检查可编织性；问题需指出位置、原因和修改建议。通过后输出与当前设计一致的材料清单、竹条编号、图文步骤。
6. 至少一个代表性扇面案例经实物试编验证；未获工艺依据的规则或教程步骤标为“待验证”。

自定义形状与扇面都支持参考图、自然语言描述、用户绘制三种输入通道。用户选择自定义形状时，大模型根据所选输入生成对应的几何载体形状供确认，而不是生成表面图样；用户绘制是其中一种输入方式。确认后选择适用编法、编辑参数并实时预览，再完成工艺检查，获取与当前形状和设计一致的材料清单、竹条编号及图文教程。生成形状本身不等于通过可编织性验证；工艺检查条件须由 B 提供依据并经团队确认，未经验证的形状不能标为可制作。

## 验收与依赖

- 共享网页项目只维护一个可运行版本；本文件为范围约定草案，需全员审核后定稿。
- 统一设计数据由 A、C、D、E 与工艺负责人 B 共同确认，写入 `docs/DESIGN_DATA.md`；工艺规则、尺寸、材料、编法及检查阈值由 B 提供依据并经试编验证，写入 `docs/CRAFT_RULES.md`。
- 扇面流程至少验证正常案例、复杂输入需简化案例和明显不合规参数案例。材料、编号、教程应对应最终预览，而非较早版本。
- 本轮不将规划能力写成已实现或已验证。共享代码库为 https://github.com/shendayongxx-dev/haining-AI-work；具体合并、发布与验收负责人待团队确认。
