# C 组 → D 组交接说明：设计数据、编辑与预览

## 1. 交接目的

C 组将用户已经预览并确认的结果交给 D 组。结果根据此前选择的载体分为两类：

- 扇面、箱盒、包：交付适配既有载体的表面图样；
- 自定义形状：交付可用于竹编的载体形状，不交付表面图案。

D 组读取同一份设计数据，在用户选择基础编法后进入编辑器，查看已确认的图样或形状在所选载体与编法下的呈现，并支持参数调整和实时预览。本轮完整联调仍先使用标准扇面。

本次交接不能只提供 PNG 或截图，必须同时提供符合 `docs/DESIGN_DATA.md` 的结构化数据。

## 2. C 组向 D 组提供

- 用户已确认的设计 JSON；
- 与 JSON 对应的扇面预览图；
- 原始输入类型：参考图、自然语言或用户绘制；
- 输出类型：标准扇面的表面图样；
- 输入草稿与确认状态；
- 坐标系、原点、方向、单位和尺寸说明；
- 图样边界和扇面边界之间的对应关系；
- 自动裁切、路径平滑和图样简化记录；
- 可编辑字段和只读字段说明；
- 转译警告及对应位置；
- `DESIGN_DATA` 版本号。
- 若为自定义形状：提供已确认的载体形状数据、形状预览、边界和尺寸或比例说明；不得使用表面图样字段冒充形状。

## 3. C 组需要 D 组提供

- D 组实际读取设计数据的接口；
- 编辑器必须读取的字段清单；
- D 组会更新的字段及更新后的输出方式；
- 坐标变换、缩放和旋转的处理约定；
- 是否需要保留原始笔迹和原始预览图；
- 读取失败或字段缺失时的错误格式；
- D 组完成真实样例读取后的验证结果。

## 4. 建议交付文件

```text
examples/fan-drawing-output.json
public/examples/fan-drawing-preview.png
```

实际位置以共享项目目录规范为准。

```text
数据格式版本：
载体类型：fan / box / bag / custom_shape
生成结果类型：固定载体为 surface_pattern；自定义形状为 carrier_shape
用户确认状态：
画布或载体尺寸：
坐标原点：
X 轴方向：
Y 轴方向：
坐标单位：
图样边界或形状边界：
是否裁切：
是否简化：
警告信息：
```

字段的正式名称必须以 `docs/DESIGN_DATA.md` 为准。

### 自定义形状分支要求

```text
此前选择自定义形状
→ 三种输入通道之一
→ C 组生成载体形状
→ 用户预览并确认形状
→ 选择基础编法
→ D 组显示该形状在所选编法下的呈现
```

D 组不得在进入编辑器前把自定义形状转换成某个固定载体的表面图片。

## 6. 联调案例

### 案例 1：简单正常图样

- 输入：扇面内的简单闭合图形；
- 预期：D 组读取后位置、比例和方向与 C 组预览一致。

### 案例 2：越界图样

- 输入：部分笔迹超出扇面边界；
- 预期：显示结果只保留扇面有效区域，数据中保留裁切记录。

### 案例 3：复杂输入需简化

- 输入：局部密集、重叠笔迹；
- 预期：D 组能显示简化结果，并能读取对应警告。

## 7. 共同验收

- [ ] D 组能够读取 C 组真实输出 JSON；
- [ ] 扇面形状和尺寸一致；
- [ ] 图样位置、比例和方向与确认预览一致；
- [ ] 图样没有镜像、翻转或意外拉伸；
- [ ] 用户未确认的草稿不会进入 D 组正式编辑流程；
- [ ] 自定义形状结果按载体形状读取，而不是按表面图样读取；
- [ ] 自定义形状确认后与固定载体分支在“选择基础编法”处汇合；
- [ ] D 组修改参数后输出数据同步更新；
- [ ] 更新后的数据仍可由 E 组读取；
- [ ] 返回输入环节时能保留或恢复必要的草稿信息。

## 8. 当前阻塞与字段变更规则

- 当前工作区尚未提供 `docs/DESIGN_DATA.md`，正式输出字段暂不能锁定；
- 若现有格式无法表达路径、确认状态或转译警告，应先提交字段变更建议；
- 字段变更建议必须说明原因、受影响模块、兼容方式和样例；
- C、D 不得各自建立含义不同的临时字段并直接进入主分支。
