## 页面变化

- “结构检查通过”旁明确显示“工艺检查：待验证”，无需展开技术记录才能看见。
- 待验证事项在主页面可读，按“参数需复核”“修正后复核”“待补设计资料”“待补工艺依据”筛选；默认展示前三项，可展开全部。
- 失败原因说明哪里有问题、为什么及下一步怎么做。结构错误导致其他项目暂不能复核时，说明先修正结构，不误说为缺少载体资料。
- 首要错误可以直接定位竹条、段或交点；只有现有数据提供真实位置时才显示定位按钮。没有位置的缺依据项目不生成假坐标。
- 保留 A 的“切换编法后重新检查并进入结构预览”流程，将文案改为可尝试的结构方案，不称默认参数已获得实物批准。
- 保留原始规则 ID、诊断、位置与依据在完整记录中。新增文案层只改变展示，不改规则结果。

主要文件：`src/modules/e/CraftCheckPanel.tsx`、`checkPresentation.ts`、`craft.css`。

## 可复现案例

输入构造见 `tests/e-check/fixtures.ts`；结果位于 `examples/e-page-acceptance/`，清单见该目录的 README 和 catalog.json。

| 案例 | 预期结构状态 | 预期总体 | 用途 |
| --- | --- | --- | --- |
| 正常圆扇结构 | passed | pending | 结构通过与工艺待验证并存 |
| 颜色分段缺口 | failed | failed | 明确失败原因与竹条定位 |
| 不存在的交点段引用 | failed | failed | 追溯错误拦截 |
| 交点挑压关系错误 | failed | failed | 编法关系错误拦截 |
| 缺少 sourceKey | pending | pending | 缺数据不误判为工艺不合格 |
| 旧快照用于当前版本 | failed | failed | 拒收版本不一致的输入 |
| 自定义上下文不足 | passed | pending | 只检查已有结构，缺项不造数据 |
| 自定义轮廓自交／退化 | failed | failed | 非法轮廓明确阻断 |

除正常结构和现有能力不足案例外，错误数据均明确标为主动注入的测试故障，不是 D 的实际生产失败案例，也不作为 B 实物验收证据。本轮没有真实工艺 passed 样例。

## 接入验收范围

浏览器验收包含主站真实的输入确认、编法选择、编辑、提交检查、待验证分类筛选、返回修改、版本递增后重查、切换支持编法后再进入结构预览、自定义鼠标绘制、移动端无页面级横向溢出等。

另在临时浏览器中单独挂载实际检查组件，输入故障样例验证错误提示、首要问题定位、失败时不显示下一步、无输入时不伪造结果，以及迟到旧失败结果不能覆盖新设计。测试挂载不增加产品调试入口，不进入正式生产构建。

核心回归入口在 A 当前基线中缺失，本轮恢复 `scripts/validation.test.ts` 与 `scripts/test-e-craft.mjs`，使原有 54 项结果可重新执行。恢复的测试会在 examples 下重生成其回归制品；本次提交只收录本轮页面案例和必要验收证据。

## 运行与课堂演示

```powershell
pnpm install --frozen-lockfile
node scripts/test-e-craft.mjs
node scripts/test-e-page.mjs
pnpm build
pnpm exec vite --host 127.0.0.1 --port 5176 --strictPort
# 服务启动后，在装有 Edge 的本机运行：
node scripts/qa-e-page-browser.mjs
```

正常流程可在主站选择圆扇、鼠标绘制（或使用已标注的绿色三角形联调样例）、确认、选择课程十字编、编辑后提交。再试平编演示，观察明确阻断、切换后重查与结构预览。自定义形状使用鼠标绘制闭合轮廓，不使用尚未接入的图文模型生成。

故障流程可演示本轮截图与 JSON，或运行自动浏览器脚本。不要向课堂观众把主动损坏数据说成真实用户故障或工艺不合格实物。

截图和检查明细：`examples/e-page-acceptance/qa/`。本地回环地址不代表已经发布为其他设备可访问的网站。
