# C 组 ↔ B 组交接说明：创意转译所需工艺依据

## 1. 交接目的

C 组负责将参考图、自然语言和用户绘制转为设计数据；B 组负责提供有资料或实物验证依据的竹编工艺事实。

C 组只执行输入处理、视觉转译和风险标记，不自行发明竹编工艺规则，也不单独宣称图样“可编”。

按当前流程，输出对象分为两类：

- 扇面、箱盒、包：输出适配所选载体的表面图样；
- 自定义形状：输出可用于竹编的载体形状，不输出表面图案。

两类结果都必须由用户先预览并确认，再进入基础编法选择。

## 2. C 组向 B 组提供

- 标准扇面原始输入；
- 输入转译后的表面图样；
- 简化前后的图样对照；
- 图样中的密集、交叉、细碎、越界等位置；
- 自动裁切、平滑或简化的处理记录；
- 无法稳定处理的输入类型清单；
- 需要 B 组判断的具体工艺问题；
- 标准扇面输出 JSON 和预览图。
- 若团队实现自定义形状分支：提供形状轮廓、尺寸或比例信息、形状预览和转译警告，不将其包装成表面图样。

## 3. C 组需要 B 组提供

- 经确认的标准扇面形状和尺寸；
- 扇面可放置图样的有效区域；
- 首版采用的基础编法及其标识；
- 与图样转译有关且已经验证的限制条件；
- 可用资料支持的参数范围及单位；
- 复杂输入需要简化或拒绝时的判定依据；
- 每条规则的来源、适用范围和验证状态；
- 尚未验证、不能作为程序规则使用的事项清单。
- 若实现自定义形状：B 组需要明确哪些“可用于竹编”的判断已有工艺依据，资料不足处必须标记“待验证”。

## 5. 边界约定

C 组可以报告：

- 图样存在密集线条；
- 图样超出载体边界；
- 输入噪点多或质量低；
- 路径发生了视觉平滑或简化；
- 当前缺少工艺依据。

C 组不得自行决定：

- 图样一定可编或一定不可编；
- 必须使用某种编法；
- 竹条宽度、间距或材料用量；
- 收边方式和真实制作顺序；
- 未在 `CRAFT_RULES.md` 中确认的工艺阈值。

## 6. 共同验收

- [ ] B 组确认标准扇面案例的载体信息；
- [ ] 所有程序化规则均能追溯到 B 组提供的依据；
- [ ] 资料不足的结论明确标为“待验证”；
- [ ] C 组没有将视觉简化误写成工艺检查；
- [ ] 输入转译警告能够关联到具体图样位置；
- [ ] B 组能查看 C 组提供的真实标准案例。
- [ ] 自定义形状不会被当作固定载体上的表面图案审核；
- [ ] 自定义形状是否可用于竹编，仅依据 B 组有来源且标明验证状态的规则。

## 7. 当前待 B 组确认的问题

- 标准扇面的具体尺寸和有效图样区域；
- 首版支持的编法；
- 是否存在已验证的最小图样尺度或最小间距；
- 哪些图样复杂度只能提示用户简化；
- 哪些信息可以进入 `DESIGN_DATA`，哪些只能保存在工艺规则中。

若没有可靠资料，请直接标记“待验证”，不要用经验值补齐。
