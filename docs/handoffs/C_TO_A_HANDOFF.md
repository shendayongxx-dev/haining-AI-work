# C 组 → A 组交接说明：创意输入转译与主流程集成

## 1. 交接目的

将 C 组负责的“参考图、自然语言、用户绘制”创意输入模块接入 A 组维护的统一网站流程。

流程必须根据用户此前选择的载体分支处理：

- 扇面、箱盒、包：生成适配既有载体的表面图样，用户预览并确认图样；
- 自定义形状：生成可用于竹编的载体形状，输出为形状而非表面图案，用户预览并确认形状；
- 两条分支确认后汇合，进入“选择基础编法”和后续编辑环节。

本轮仍以标准扇面作为完整验证案例；自定义形状分支的产品含义和页面走向按上述流程保留，具体实现深度由团队范围文档确定。

## 2. C 组向 A 组提供

- 创意输入方式选择组件；
- 标准扇面直接绘制组件，兼容鼠标、触屏和触控笔；
- 根据结果类型展示“图样预览与确认”或“形状预览与确认”的组件；
- 参考图、自然语言和用户绘制的统一输出接口；
- 用户原始输入、预览结果和确认结果；
- 摄像头隔空绘制实验入口（若本轮完成）；
- 摄像头不可用或权限被拒绝时，回退至直接绘制的处理；
- 标准扇面输出 JSON 和预览图；
- 运行说明、验证结果及已知限制。

## 3. C 组需要 A 组提供

- 共享项目或代码仓库及当前开发分支；
- 项目启动方法、技术框架和目录规范；
- 创意输入模块所在页面及路由；
- 当前所选载体的数据结构和传入方式；
- 草稿及已确认设计数据的保存位置；
- 用户确认后进入“选择编法”的导航方法；
- 项目统一的加载、错误、返回和权限提示样式；
- 已确认的 `docs/DESIGN_DATA.md`。

## 4. 建议组件接口

以下仅表示组件职责；字段名称应结合项目实际代码确定。

```ts
type CreativeInputProps = {
  carrier: CarrierData;
  initialDraft?: CreativeDraft;
  onPreview: (draft: CreativeDraft) => void;
  onConfirm: (designData: DesignData) => void;
  onCancel: () => void;
};
```

`carrier` 必须保留用户此前选择的载体。C 组不能仅依据输入内容自行判断输出图样还是形状：

```text
carrier = fan / box / bag
→ surface_pattern

carrier = custom_shape
→ carrier_shape
```

以上值仅用于说明分支语义，正式枚举名称以 `docs/DESIGN_DATA.md` 为准。

建议页面状态：

```text
选择作品载体
→ 选择输入方式
→ 正在输入
→ 正在转译
→ 固定载体：预览并确认图样
  或自定义形状：预览并确认形状
→ 选择基础编法
```

只有处于“用户已确认”状态的设计数据才能进入后续流程。

## 5. A 组集成要求

1. 从当前载体选择结果进入创意输入页面；
2. 将用户此前选择的载体类型、已有形状和尺寸传给 C 组组件；
3. 保存 C 组返回的草稿，用户返回修改时不得丢失；
4. 固定载体显示“预览并确认图样”，自定义形状显示“预览并确认形状”；
5. 用户确认后保存正式设计数据；
6. 将同一份正式设计数据传给 D 组；
7. 不得绕过确认状态直接进入“选择编法”。

## 6. 共同验收

- [ ] 能从“选择扇面”进入“用户绘制”；
- [ ] 能在扇面内绘制并生成预览；
- [ ] 选择自定义形状时，输出被识别为载体形状而非表面图案；
- [ ] 自定义形状经过独立的“预览并确认形状”步骤后再进入基础编法；
- [ ] 返回修改后原笔迹仍然存在；
- [ ] 用户确认后才生成正式输出；
- [ ] 确认结果能传给 D 组页面；
- [ ] 刷新、返回或发生错误时有明确提示；
- [ ] 摄像头不可用时可以继续使用直接绘制；
- [ ] 主流程中规划功能没有被标为已实现。

## 7. 当前阻塞与未决事项

- 当前工作区尚未提供 `docs/DESIGN_DATA.md`，最终字段映射不能锁定；
- A 组需明确全局状态保存和页面导航方案；
- 摄像头隔空绘制建议作为实验增强功能，不阻塞标准扇面闭环；
- 箱盒、包和自定义形状的实现深度需由团队范围文档确定，但其流程语义不得改写：前三者中的固定载体输出表面图样，自定义形状输出载体形状。
