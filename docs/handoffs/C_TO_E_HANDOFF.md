# C 组 → E 组交接说明：转译信息与工艺检查输入

## 1. 交接目的

C 组向 E 组说明创意输入的来源、用户确认状态、转译过程和风险信息。E 组依据 B 组确认的工艺规则，对 D 组编辑后的最新设计数据执行检查，并生成材料、编号和教程。

C 组不负责给出“可编织”结论，也不负责材料计算和制作步骤。

结果对象必须区分：

- 扇面、箱盒、包：已确认的表面图样；
- 自定义形状：已确认的载体形状，不是表面图案。

## 2. 数据流约定

```text
C 组生成并由用户确认
→ D 组读取和编辑
→ E 组读取 D 组更新后的同一份设计数据
```

E 组正式检查的对象应是 D 组编辑后的最新版本，而不是 C 组最初预览时的旧版本。

## 3. C 组向 E 组提供

- 输入通道：参考图、自然语言或用户绘制；
- 载体类型和输出结果类型；
- 用户是否已经确认；
- 原始输入的引用或必要摘要；
- C 组执行过的裁切、平滑和简化处理；
- 转译警告及其位置；
- 输入质量问题；
- 工艺状态为“待验证”的事项；
- 与标准扇面预览对应的设计数据版本。
- 若为自定义形状：提供已确认形状的边界、尺寸或比例、形状预览和转译警告。

## 4. C 组需要 E 组提供

- 校验状态的数据格式；
- 错误、警告和待验证三类结果的区分方式；
- 问题位置如何关联到图样或路径；
- 校验失败后建议用户返回的页面；
- E 组是否需要原始笔迹、预览图或转译过程记录；
- E 组读取标准案例后的结果；
- 因输入数据不足而无法校验时的错误表达。

## 5. C 组可提供的风险信息

```text
图样存在密集或重叠线条
图样部分超出载体边界
自定义形状轮廓存在断裂、自交或输入信息不足
输入图像模糊或信息不足
用户笔迹包含大量噪点
局部路径已被平滑或简化
摄像头追踪发生过短暂丢失
当前缺少工艺资料支持
```

这些信息是转译或输入质量说明，不等同于工艺检查结论。

## 6. C 组不得替 E 组输出

- “设计已通过可编织性检查”；
- 竹条规格和材料用量；
- 竹条编号；
- 必须采用的编法；
- 收边方式；
- 真实制作步骤；
- `CRAFT_RULES.md` 未支持的修改建议。

## 7. 建议警告内容

以下只说明应包含的信息，正式字段名以 `docs/DESIGN_DATA.md` 为准。

```json
{
  "inputChannel": "user_drawing",
  "resultType": "surface_pattern",
  "confirmationStatus": "confirmed",
  "translationWarnings": [
    {
      "code": "DENSE_LINES_SIMPLIFIED",
      "message": "局部密集线条已进行视觉简化",
      "location": "待按统一位置格式填写",
      "craftStatus": "pending_validation"
    }
  ]
}
```

该示例不能替代正式数据规范。

自定义形状分支的 `resultType` 必须表达“载体形状”，不能沿用 `surface_pattern`。正式枚举名称由 `docs/DESIGN_DATA.md` 确定。

## 8. 共同验收

- [ ] E 组读取的是 D 组编辑后的最新数据；
- [ ] E 组能识别输入来源和用户确认状态；
- [ ] 转译警告不会被误认为工艺检查结果；
- [ ] 问题位置能够映射回当前预览；
- [ ] 缺少工艺依据时显示“待验证”，而不是自动通过；
- [ ] 检查失败后用户能够返回正确环节修改；
- [ ] 标准扇面案例的检查结果与当前预览版本一致。
- [ ] 自定义形状按已确认的载体形状检查，不被误当作固定载体表面图案；
- [ ] E 组使用 D 组编辑后的最新形状或图样，而非 C 组旧预览。

## 9. 当前阻塞与未决事项

- 当前工作区尚未提供 `docs/DESIGN_DATA.md`，警告、确认状态和问题位置的正式字段尚未锁定；
- B、E 需共同确定工艺规则与检查结果的关系；
- A 需确定检查失败后的页面返回路径；
- C、E 需确认 E 是否需要保留原始输入路径。
