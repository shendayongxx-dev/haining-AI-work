# 工艺检查到图文制作说明书：最终效果与开发总流程

状态：**目标与实施路线草案，供 A/B/C/D/E 共同确认**。本文描述最终要达到的能力，不表示当前页面已经能判断实物可制作，也不直接修改公共设计数据格式。编法、材料、尺寸、收边和验收阈值以 B 的试编证据及团队确认结果为准。

## 一、最终要让用户得到什么

用户确认图样或形状、选择编法并完成编辑后，系统针对**当前设计版本**给出可追溯的结论：

1. **能否制作**：明确显示“可制作”“需修改”或“依据不足”。“结构数据正确”只是其中一项，不能单独等同于“可制作”。
2. **不能制作时怎么改**：指出具体位置（竹篾、交点、边缘、柄口或图样区域）、触发的规则、测得的数值或事实、修改建议。用户修改后重新计算、重新检查。
3. **依据不足时缺什么**：明确缺少的材料规格、参数范围、连接/收边试编记录或自定义形状上下文；不输出肯定的制作结论。
4. **可制作时的备料单**：列出材料和工具、规格、数量、每根竹篾的编号与裁切长度、备料余量、总量，以及这些数字对应的设计版本和工艺依据。不把成品可见长度直接当采购或裁切长度。
5. **可制作时的图文说明书**：以新手能按顺序操作为标准，逐步写明“拿哪根、放在哪里、从哪侧穿、压在谁上/下、做到什么状态、如何自查”。每步有对应的局部示意图；裁剪、收边、柄口连接等难以只靠几何图说明的步骤，使用 B 审定的实拍图或照片标注。
6. **版本一致**：图样、编法、载体、尺寸、材料或参数变化后，原检查结论、备料单和教程立即失效；重新检查通过后才生成新版本资料。

最终说明书应覆盖备料检查、排经、逐根穿纬、压挑和校正、裁剪、收边、连接、成品复核与常见错误处理。它应让未参与开发的新手仅凭说明完成一个在已验证范围内的作品，并由 B 对成品复核。**超出已验证材料、形状、编法或参数范围的设计，不承诺自动给出可制作教程。**

## 三、从现在到完成的开发总流程

以下是**研发交付顺序**，不是用户在网页上的点击顺序。每阶段达到出口条件后再进入依赖它的下一阶段。

| 阶段 | 负责与工作 | 交付物 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 0. 确定首个可制作范围 | A 组织 B/C/D/E 选定一个载体、一个编法、材料规格及允许参数区间，约定“可制作/需修改/依据不足”的含义。 | 首个基准案例、支持范围和失败样例清单。 | 团队确认同一个案例和共同输入数据；未覆盖组合默认不开放正式教程。 |
| 1. B 试编与规则固化 | B 按基准案例实做并记录：材料批次与尺寸、竹篾可操作长度、压挑顺序、边缘与柄口处理、损耗、成品偏差、失败条件和照片。 | 可追溯的试编记录、可执行规则、备料与教程操作依据。 | 每条准入规则有适用条件、判定方法、证据和复核人；失败与临界样例可重现。 |
| 2. D 补制作级快照 | D 从当前设计计算毛坯、逐根裁切与余量、裁剪线、收边和连接位置、每步竹篾与交点；自定义形状补完整上下文。 | 带稳定 ID、毫米坐标和来源键的制作数据，不只是一张预览图。 | 同一输入重复计算结果一致；参数改变会重算所有受影响字段；缺失信息显式为空，不猜数值。 |
| 3. C/A 补设计语义 | C 保证图样元素 ID、几何和来源稳定；A 让用户确认重点图案或明确无重点图案，并管理设计版本。 | E 可消费的已确认设计与重点图案声明。 | 图样/声明/载体变化能使旧检查失效；重点图案不靠颜色或面积猜测。 |
| 4. 重构 E 的制作判定 | E 将 D 数据、B 规则和匹配的试编证据逐项核验；把结构正确、工艺条件、证据覆盖分别记录，再汇总三态结果。 | 带具体位置、原因、建议、规则/证据 ID 和版本键的检查结果。 | “可制作”只在全部必要条件通过且证据覆盖时出现；错误与缺证据不会被归成通过；无条件 `pending` 的硬编码被有依据的覆盖判断替代。 |
| 5. 材料计算 | D/B 定义真实备料算法，A 接入与展示；E 负责放行与版本校验。 | 逐根竹篾裁切表、其他材料/工具清单、总量和余量。 | 每一项能追溯到当前结构与 B 规则；抽样与实物消耗核对；缺数据时不显示猜测数量。 |
| 6. 图文教程生成 | D 输出逐步结构状态及高亮图；B 提供并审核动作、收边/连接实拍和检查点；A 组装页面与可保存说明书。 | 每步有文字、示意图、竹篾编号、操作方向、完成标准和常见错误的说明书。 | 图与文字引用同一操作 ID 和设计版本；顺序能对应 B 实际试编过程；不由生图模型发明工艺动作。 |
| 7. 端到端及新手验收 | A/E 核对状态与过期机制；B 找未参与开发的人按说明书独立制作并复核成品；C/D 修复发现的数据问题。 | 通过与失败案例、误判记录、新手卡点记录、修订后的规则/图文。 | 新手能够按说明独立完成已验证案例；失败和证据不足的设计不会拿到正式教程。 |
| 8. 分批扩展与部署 | 按相同证据链扩到其他编法、扇型、参数和自定义形状；A 配置后端与持久化。 | 按组合标注的支持范围、版本化资料和线上服务。 | 每新增范围都有 B 证据、D 数据、E 规则、材料核算和新手验证；线上结果可保存和复查。 |

阶段 1、2、3 可以并行准备；**阶段 4 必须使用真实的 B 证据与 D 快照联调**。阶段 5、6 依赖阶段 4 的可靠放行，不能先把按钮打开再补判据。

## 四、模块之间必须对齐的最小信息

公共格式由团队评审后写入 `docs/DESIGN_DATA.md`；以下只是接口核对清单，不是擅自新增的正式字段。

- **设计来源**：`designId`、`designRevision`、已确认生成结果、载体与编法版本、材料规格及参数、重点图案声明。
- **D → E**：完整结构快照与 `sourceKey`，包括每根竹篾和每个交点的稳定 ID、毛坯/成品几何、长度、操作顺序、边缘和连接上下文。
- **B → E**：规则版本、适用范围、阈值与测量方法、试编证据 ID、材料批次或规格、复核状态。证据必须能判断“是否覆盖当前设计”，不能只有一张泛用示例照片。
- **E → A/材料/教程**：总体三态结论、逐项结果、具体位置与建议、`sourceKey`、`assessmentKey`、证据引用，以及是否允许生成正式备料单和教程。
- **材料 → 教程**：同一组竹篾 ID、裁切长度和材料版本；教程每一步引用真实的 D 操作 ID、竹篾 ID 与图示状态。

若上述任一版本键变化，旧 E 结论、备料单与教程都必须失效。任何“可制作”结论都应能回答：用了哪版规则、哪份试编记录、哪版结构快照。

## 五、服务与模型调用边界

- 现有 `qwen-image-2.1-turbo` 继续用于前段创意图生成；它的图片不能充当工艺通过的证据。
- 可制作性检查、材料数量、竹篾长度和穿织顺序由 **B 规则＋D 结构数据＋E 确定性检查**产生，不要求新增付费大模型。
- 教程中的竹篾/交点示意图优先根据 D 快照绘制 SVG 或其他矢量图；真实收边和连接动作使用 B 审定的照片。若以后用语言模型润色文字，只能改写已经审定的动作，不能自行增加步骤、尺寸或可制作结论。
- 本机演示可沿用现有服务。若让公开网站保存设计、生成图、证据、检查结果与说明书，需要可部署后端和持久化存储；GitHub Pages 不能运行当前本地 API。

## 六、首个基准案例与完成标准

建议先选“圆扇＋十字编（内部 ID `CROSS-COURSE-2X2-V1`）＋固定材料规格＋固定参数区间”。原因是该编法已进入当前 B/E 检查范围；但**它仍缺实物试编依据**，不能沿用旧平编 `CROSS-1X1-V1` 的材料数字直接开放制作。最终选择和规格由 A/B/C/D/E 共同确认。

首个案例完成的判定：

1. B 有覆盖该组合与参数范围的试编记录；D 给出完整制作数据；E 对通过、失败、缺证据三个样例分别给出正确结论。
2. 通过样例生成准确备料单和逐步图文；失败与缺证据样例不能生成正式教程。
3. 新手只依靠说明书完成制作，B 按预先约定的成品标准复核。新手人数、允许求助次数和合格阈值由团队在试验前确定，不能事后降低标准。
4. 用户更改设计后，旧结论、清单和教程立即失效；重新检查后生成新版本。

## 七、现在的第一步

A 组织 B、D、E 对首个基准案例开一次接口评审；C 提供对应的真实创意候选。评审只需先锁定四份东西：**支持范围与判定标准、B 的试编记录模板、D 缺失字段清单、E 的逐项判定与证据覆盖清单**。这四份确定后，才能按上表推进代码实现和新手验收。
