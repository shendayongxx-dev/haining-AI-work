# 竹编 DIY 平台（团队共享项目）

本仓库供五人团队共同开发一个网页项目。现有 React + TypeScript 集成骨架，可浏览完整页面路径；C/D/E 的真实功能尚未接入，**这不是完整 Demo**。

## 已确认的 Demo 范围

- 扇面：三种输入通道生成适配扇面的表面图样，确认后走通选编法、编辑与实时预览、工艺检查、材料清单、竹条编号和图文教程。
- 自定义形状：三种输入通道生成几何载体形状，确认后走通同样的后续流程。生成的是形状，不是表面图样。
- 箱盒、包：仅显示载体选项，不接入生成或后续流程。

三种输入通道为参考图、自然语言描述和用户绘制。详细步骤见 [产品范围](docs/PRODUCT_SCOPE.md) 与 [用户流程](docs/USER_FLOW.md)。

团队确认的范围优先于早期 PRD V0.1：用户绘制和自定义形状属于前序开发，不排入后续版本。PRD 中的其他新增功能须另行确认。

## 当前状态与下一步

当前页面骨架包括载体、三种输入入口、生成过渡、候选确认、选编法、SVG 预览、检查和资料页。绘制入口支持鼠标、触屏、触控笔及撤销、重做、清空。绿色三角形是接口联调样例；参考图和自然语言目前只收集输入，三通道均使用明确标注的接口占位候选，尚未生成真实结果。页面切换与视觉动画已加入。五人仍需确认扇面标准案例、工艺规则、自定义形状边界及公共数据格式，并补齐工艺规则、验收案例和模块输出样例。

本仓库由产品与集成负责人 A 维护可运行主版本并负责合并与演示发布；建议 B 负责工艺验收，五人共同验收端到端流程。该分工建议仍待团队确认。

## 启动骨架

安装 Node.js 20.19+ 后，在仓库根目录执行 `pnpm install`、`pnpm dev`。构建命令为 `pnpm build`。团队接入点、当前占位能力和共同案例见 [集成说明](docs/INTEGRATION.md)。

依赖已安装，并已通过 TypeScript 检查和 Vite 生产构建。演示边界见 [DEMO_FAN_BOUNDARY_V0.1](docs/DEMO_FAN_BOUNDARY_V0.1.md)。
